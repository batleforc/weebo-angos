- **API version:** `angos.weebo.io/v1alpha1`
- **Scope:** Namespaced
- **Short names:** `ali`
- **Guide:** [Install via Helm](/docs/guides/install)

An Angos registry the operator runs in this namespace: its
`Deployment`, its configuration (rendered from this spec, its
repositories and identities) and the objects around them. `Ready` tells
whether its pods run the desired configuration.

## Example

```yaml
apiVersion: angos.weebo.io/v1alpha1
kind: AngosLocalInstance
metadata:
  name: my-localinstance
  namespace: team-a
spec:
  storage:
    s3:
      endpoint: https://s3.example.com
      bucket: registry
      region: us-east-1
      credentialsSecretRef:
        name: registry-s3
  auth:
    tokenService:
      realm: https://registry.example.com/token
```

## Spec fields

| `affinity` | `object` | no |  |  |
| `auth` | `object` | no | `{}` | `[auth]`: who may authenticate. |
| `cache` | `object` | no |  | `[cache]`: unset, Angos caches in memory. |
| `env` | `object[]` | no |  | Rarely needed (Angos reads no secret from its environment). Secrets read here must be labelled `angos.weebo.io/credential: "true"`; `RUST_LOG` is the operator's (`logLevel`). |

| `eventWebhooks` | `object[]` | no |  | `[event_webhook.<name>]`: told of pushes, pulls and deletions. |

| `extraVolumeMounts` | `object[]` | no |  |  |

| `image` | `object` | no |  | The Angos image. Its repository must be one the operator allows (`managedInstances.allowedImages`). |
| `imagePullSecrets` | `object[]` | no |  |  |
| `logLevel` | `string` | no | `"info"` | `RUST_LOG` of the pods (e.g. `info`, `warn,angos=debug`); the operator always adds `angos::configuration::watcher=info`, the reload messages it reads. |
| `networkPolicy` | `object` | no |  | A `NetworkPolicy` around the pods: unset, none. |
| `nodeSelector` | `object` | no |  |  |
| `podAnnotations` | `object` | no |  |  |
| `podLabels` | `object` | no |  |  |
| `podSecurityContext` | `object` | no |  | Unset: non-root 65534 (the image's user), seccomp `RuntimeDefault`. |
| `priorityClassName` | `string` | no |  |  |
| `pruneLock` | `object` | no | `{"windowHours":24}` | The prune lock (spec 6.6): no `AngosMaintenance` prune runs while a repository was released less than `windowHours` ago (its data goes at the next prune: time to notice and recreate it). |
| `reload` | `object` | no | `{"mode":"Hot","onUnconfirmed":"Wait","timeoutSeconds":180}` | How a new configuration reaches the pods. |
| `replicas` | `integer` | no | `1` | The server's pods. More than one needs an S3 store and `worker.enabled`, and runs once Angos found the store's conditional writes atomic (`status.conditionalWrites`); until then, one. |

| `securityContext` | `object` | no |  | Unset: read-only root filesystem, no capability, no escalation. |

| `service` | `object` | no | `{"port":8000,"type":"ClusterIP"}` |  |
| `serviceAccount` | `object` | no | `{"create":true}` |  |
| `storage` | `object` | yes |  | Where Angos keeps blobs and metadata. Read at startup only: a change of the store waits for the annotation `angos.weebo.io/confirm-storage` (set to `status.pendingBootHash`), then rolls the pods. Pointing an instance at another, empty store makes it serve an empty registry: no data moves. |
| `terminationGracePeriodSeconds` | `integer` | no |  | Unset: three times `global.shutdownDrainSecs` (30) plus 10. |
| `tolerations` | `object[]` | no |  |  |
| `tracing` | `object` | no |  | `[observability.tracing]`: OTLP traces. Startup only. |
| `ui` | `object` | no |  | `[ui]`: Angos's web UI. |
| `worker` | `object` | no |  | `angos worker`: a `<name>-worker` Deployment draining the background jobs (cache fills, replication, scans, indexes) from a durable queue (`[global.job_queue]`) instead of the server's own loops. |
