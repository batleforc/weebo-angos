- **API version:** `angos.weebo.io/v1alpha1`
- **Scope:** Namespaced
- **Short names:** `aid`
- **Guide:** [Install via Helm](/docs/guides/install)

A Basic identity of an Angos instance (`[auth.identity]`): a robot, a
CI, a scanner. The operator generates its password (or adopts one),
hashes it with Argon2id for the instance's configuration, and writes the
clear password to its targets once every pod of the instance accepts
it. Angos verifies a Basic password on every request (≈ 19 MiB and tens
of milliseconds each): workloads should rather use their
ServiceAccount's token (`auth.kubernetes`).

## Example

```yaml
apiVersion: angos.weebo.io/v1alpha1
kind: AngosIdentity
metadata:
  name: my-identity
  namespace: team-a
spec:
  registryHost: registry.example.com
  rotationDays: 90
```

## Spec fields

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| [`adoptSecretRef`](#spec.adoptSecretRef) | `object` | no |  | An existing password to keep (an identity moved from another tool), in a Secret of this namespace labelled `angos.weebo.io/credential: "true"`: read once, at creation. |
| [`instanceRef`](#spec.instanceRef) | `object` | no |  | The instance: unset, the only one of this namespace. An instance of another namespace must accept this one (`repositorySelector.namespaces`). |
| `registryHost` | `string` | no |  | The registry's public host (e.g. `registry.example.com`): adds a `.dockerconfigjson` key to the targets. |
| `rotationDays` | `integer` | no |  | A new password every this many days; the annotation `angos.weebo.io/rotate` (a new value) rotates it at once.<br /><br />Constraints: `minimum: 1` |
| [`secretTargets`](#spec.secretTargets) | `object[]` | no |  | Where the credentials are written (keys `username`, `password`, and `.dockerconfigjson` with `registryHost`). Unset: the Secret `<name>-credentials` of this namespace. |
| `username` | `string` | no |  | The username (`identity:<username>` in access rules). Default: the CR's name. Unique on the instance, never an OIDC provider's name.<br /><br />Constraints: `pattern: ^[A-Za-z0-9._-]+$` |

### `spec.instanceRef` [#spec.instanceRef]

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `kind` | `string` | no |  | The kind of instance a reference designates.<br /><br />Values: `"Instance"`, `"LocalInstance"` |
| `name` | `string` | yes |  | `metadata.name` of the instance. |
| `namespace` | `string` | no |  | Namespace of a `LocalInstance`. Defaults to this object's own; required on a cluster-scoped object. Another namespace's local instance must share itself with this one (its `sharedWith`). |

**Rules**

- namespace only applies to kind LocalInstance — `!has(self.namespace) || !has(self.kind) || self.kind == 'LocalInstance'`

### `spec.secretTargets[]` [#spec.secretTargets]

| Field | Type | Required | Default | Description |
| --- | --- | --- | --- | --- |
| `backend` | `string` | no | `"kubernetes"` | `kubernetes` (default) or `vault`. A Vault target reuses the Vault connection (address, mount, auth) the instance configures, which it must then do.<br /><br />Values: `"kubernetes"`, `"vault"` |
| `name` | `string` | yes |  | Kubernetes: the `Secret` name. Vault: names the default path `<pathPrefix>/<namespace>/<name>` when `path` is unset. |
| `namespace` | `string` | no |  | Kubernetes `Secret` namespace (Vault: the namespace segment of the default path). Defaults to the CR's own namespace; required on cluster-scoped CRs. A namespaced CR may only name its own namespace. |
| `path` | `string` | no |  | Vault only: explicit KV v2 path under the instance's mount. It must stay under `<pathPrefix>/<namespace>/` (this object's namespace, or the target's on a cluster-scoped object), unless the instance's `pathGrants` open it to this object. |
