---
title: Reason codes
description: Every code the operator puts on a condition, an Event or an admission denial.
---

Every condition, Event and admission denial the operator writes carries one
of these codes, never free text: alerts, scripts and `kubectl` filters can
rely on them. The list is generated from the operator's source, so it
matches the installed version.

- **Blocking**: `Ready` turns `False` with this reason, and every failed
  reconcile records a `Warning` Event with it ([Events](/docs/reference/events)).
  An admission webhook denial carries one too (HTTP 403, the code as its
  reason).
- **Advisory**: the CR still works. `Reconciled` is the reason of `Ready: True`; the
  others are a condition of their own (its `type` is the code, its
  `status` `"True"`) or a lifecycle Event.

Every CR's `Ready` reason also labels the reconcile counter
([Metrics & health](/docs/reference/metrics)), so a code can be graphed and
alerted on. To find where one shows up right now:

```bash
kubectl get events -A --field-selector reason=InvalidSpec
```

| Code | Severity | Shows as | Meaning |
| --- | --- | --- | --- |
| `Reconciled` | advisory | `Ready: True` | `Ready: True` — the one success reason every reconciler uses. |
| `InvalidSpec` | blocking | `Ready: False`, Event (`Warning`), admission denial | The spec breaks a rule Angos would refuse at load (a missing field, a value out of range, a duplicate, a reference to nothing), a CEL rule doesn't compile, `extraConfig` sets a path a typed field renders, or an access subject is too broad for `jobs`/`admin`. Only a change of the spec clears it. |
| `InstanceNotFound` | blocking | `Ready: False`, Event (`Warning`) | `spec.instanceRef` names no `AngosLocalInstance` the operator sees (or, unset, there is none in the namespace to default to). |
| `InstanceAmbiguous` | blocking | `Ready: False`, Event (`Warning`) | `spec.instanceRef` is unset and several instances could serve the object. |
| `InstanceNotAllowed` | blocking | `Ready: False`, Event (`Warning`) | The instance named is out of reach: one of another namespace that doesn't accept objects of this one, or outside the namespace the operator is limited to. |
| `InstanceBindingChanged` | blocking | `Ready: False`, Event (`Warning`) | `spec.instanceRef` by name now designates another instance than the one recorded in `status.instance`: not followed until `spec.instanceRef.namespace` says which. |
| `InstanceInUse` | blocking | `Ready: False`, Event (`Warning`) | The instance is being deleted while repositories, identities or maintenances are still bound to it: it waits for them. |
| `SecretNotAllowed` | blocking | `Ready: False`, Event (`Warning`), admission denial | A `Secret` the operator would read, or the instance's pods would mount, lacks the label `angos.weebo.io/credential: "true"`. |
| `SecretMissing` | blocking | `Ready: False`, Event (`Warning`) | A referenced `Secret`, or its key, is missing. |
| `OwnedObjectConflict` | blocking | `Ready: False`, Event (`Warning`) | An object the operator would create exists and isn't the instance's (no owner reference, no `managed-by` label): never taken over. |
| `StorageChangePending` | advisory | condition `StorageChangePending: True`, Event (`Normal`) | The storage changed (type, endpoint, bucket, region, prefix): the new startup layer waits for the annotation `angos.weebo.io/confirm-storage` set to `status.pendingBootHash`. |
| `DisruptiveUpdatePending` | advisory | condition `DisruptiveUpdatePending: True`, Event (`Normal`) | A change that rolls the pods (a startup key, the image) waits: they share a single-writer volume, so they are recreated — an outage. The annotation `angos.weebo.io/allow-disruptive-update: "true"` lets it through. |
| `WorkloadNotReady` | blocking | `Ready: False`, Event (`Warning`) | The instance's pods aren't ready on the desired startup layer yet (rolling out, or not scheduled; the worker before the server when the durable queue is turned on). |
| `ReplicasHeld` | advisory | condition `ReplicasHeld: True`, Event (`Normal`) | `replicas > 1` runs one server pod: Angos hasn't probed the store's conditional writes yet, or found them not atomic (claims and immutable tags would race). The annotation `angos.weebo.io/allow-advisory-claims: "true"` lets the replicas through anyway. |
| `BootRejected` | blocking | `Ready: False`, Event (`Warning`) | The new pods don't start (crash loop, `/readyz` never ready): the message quotes the last error they logged. The previous pods keep serving. |
| `ConfigPropagating` | blocking | `Ready: False`, Event (`Warning`) | The hot layer was written and the pods haven't all confirmed loading it yet. |
| `ConfigRejected` | blocking | `Ready: False`, Event (`Warning`) | A pod refused the hot layer: the last accepted one was put back. Only a change (of the spec, a repository, a Secret) is tried again. |
| `ReloadUnconfirmed` | advisory | condition `ReloadUnconfirmed: True`, Event (`Normal`) | No pod said whether it loaded the hot layer within `reload.timeoutSeconds` (`onUnconfirmed: Wait`). |
| `PrefixConflict` | blocking | `Ready: False`, Event (`Warning`), admission denial | Another repository of the instance has the same prefix or one that overlaps it (`team` and `team/app`): the older one is rendered. |
| `UsernameConflict` | blocking | `Ready: False`, Event (`Warning`) | Another identity of the instance has the same username, or it equals the name of an OIDC provider. |
| `DeletionNotAllowed` | blocking | `Ready: False`, Event (`Warning`) | Deleting the repository (or pruning a downstream) would erase its data at the next prune: it needs the annotation `angos.weebo.io/allow-data-deletion: "true"`. |
| `MaintenanceFailed` | blocking | `Ready: False`, Event (`Warning`) | The maintenance run failed (its Job's exit code and last log lines in `status.lastRun`). |
| `MaintenanceTimeout` | blocking | `Ready: False`, Event (`Warning`) | The maintenance run outlived `timeoutSeconds`. |
| `MaintenanceInterrupted` | blocking | `Ready: False`, Event (`Warning`) | A run recorded as running has no Job any more (the operator or the Job was interrupted): not retried. |
| `MaintenanceSkipped` | advisory | condition `MaintenanceSkipped: True`, Event (`Normal`) | A prune run was skipped by the prune lock (a repository not rendered or released recently, the instance not confirmed): the message says why. |
| `MaintenanceDeferred` | advisory | condition `MaintenanceDeferred: True`, Event (`Normal`) | Another writing task runs on the instance: this one waits for the next pass. |
| `MaintenanceRunning` | advisory | condition `MaintenanceRunning: True`, Event (`Normal`) | A run is in progress. |
| `MaintenanceSuspended` | advisory | condition `MaintenanceSuspended: True`, Event (`Normal`) | The schedule is suspended (`suspend`, or the instance rolls out or upgrades). |
| `UpgradeNotAllowed` | blocking | `Ready: False`, Event (`Warning`) | The image tag goes back below `status.version` or jumps more than one minor: it needs `angos.weebo.io/approved-upgrade` set to that tag. |
| `LeavesWatchScope` | blocking | `Ready: False`, Event (`Warning`) | An update would take a CR still carrying the finalizer out of the operator's label selector (`watch.labelSelector`): refused at admission. |
| `KubernetesApiError` | blocking | `Ready: False`, Event (`Warning`), admission denial | A Kubernetes API call of the operator itself failed (reading a CR or a Secret, applying an object, patching a status) — retried. |
| `ExtraConfigUsed` | advisory | condition `ExtraConfigUsed: True`, Event (`Normal`) | `extraConfig` is rendered: what it sets isn't checked by the operator, only by Angos at load. |
| `RuleMayFail` | advisory | condition `RuleMayFail: True`, Event (`Normal`) | A CEL rule failed to evaluate on a plausible request: in an access policy, an error is a denial. |
| `IndexMemoryRisk` | advisory | condition `IndexMemoryRisk: True`, Event (`Normal`) | The index jobs may outgrow the container's memory limit (`global.jobs.index × global.limits.maxIndexEntries`). |
| `GcGraceLowered` | advisory | condition `GcGraceLowered: True`, Event (`Normal`) | `global.gcGraceSecs` was lowered on an instance in service. |
| `VolumeNotResized` | advisory | condition `VolumeNotResized: True`, Event (`Normal`) | The storage volume asks for another size than its existing claim: a claim is never resized by the operator. |
| `StorageCredentialsRotated` | advisory | condition `StorageCredentialsRotated: True`, Event (`Normal`) | The S3 credentials changed alone: the pods rolled without a confirmation. |
| `IssuerDiscoveryNotBound` | advisory | condition `IssuerDiscoveryNotBound: True`, Event (`Normal`) | `auth.kubernetes` is used: the instance's account must be bound to `system:service-account-issuer-discovery` (gitops). |
| `ConfigReloaded` | advisory | Event (`Normal`) | Every pod loaded the new hot layer (Event only). |
| `ConfigRolledOut` | advisory | Event (`Normal`) | The pods rolled onto a new startup layer or image (Event only). |
| `TokenKeyRotated` | advisory | Event (`Normal`) | The token service's key was rotated: every token is invalid (Event only). |
| `PasswordRotated` | advisory | Event (`Normal`) | An identity's password was rotated (Event only). |
| `MaintenanceStarted` | advisory | Event (`Normal`) | A maintenance run started (Event only). |
| `Released` | advisory | Event (`Normal`) | The finalizer finished — cleanup done, or the CR force-orphaned (Event only). |
